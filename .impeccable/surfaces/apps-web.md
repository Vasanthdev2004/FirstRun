# M4 interface brief

Mode: Operate. Maintainers inspect setup failures, review independent proof, and
resolve only supported human decisions. The owner requested direct development;
this is a code-led implementation, with no additional visual approval round.

## Direction contract

THESIS: An execution score, not a dashboard of invented productivity metrics.

OWN-WORLD: Daylight developer workspace; cool white, graphite, restrained blue,
semantic outcome labels. Workhorse UI type; monospace only for code and identities.

STORY: Find a repository, distinguish main from its repair, inspect evidence, act.

FIRST VIEWPORT: Compact navigation rail, repository heading and primary run action,
revision/health ledger, then real case rows. Unconfigured installations show the
actual setup requirements instead of populated sample runs. Case detail selects
an execution stage while the tested revision and proof boundaries remain visible.

FORM: Operational score, grounded candidate 5, seed `1e8df585`. Stage selection is
the signature interaction; reduced motion preserves its immediate state change.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Constraints

The product brief's calm developer language and truthful state override the visual
helper's unrelated catalog motifs. The six challengers lose product clarity here:
barcode fields hide task state; film rails obscure labels; club scrawl impairs
legibility; poster walls need nonexistent visual artifacts; diving introduces false
operational concepts; industrial quote grammar adds noise. Keep their useful
discipline: dense alignment, persistent selection, decisive action emphasis,
keyboard focus, anchored provenance, and explicit disabled-state treatment.
No marketing claims, stock images, simulated progress, or automatic demo login.
